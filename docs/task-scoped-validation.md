# 按任务选择 PR 检查

用户确认：小改动只跑构建、专项和直接相关回归；整套测试保留为手动入口。战士浏览器命中率暂不作为肉怪任务的验收项，原失败记录不改写为通过。

- 纯文档、Skill、此验证流程自身的改动，只执行 diff 和范围规则检查。
- 游戏 PR 开发前确定 `.github/validation-plan.json`：`reason` 说明检查理由，`files` 列出所有非文档/非本流程文件的精确路径，`tests` 列出要运行的 `scripts/validate-*.mjs`。
- 每个游戏 PR 必须更新清单；未覆盖文件、缺失测试或测试失败都使 CI 失败。清单仍需人工审查其充分性，路径匹配不能证明测试覆盖率。
- 普通 PR 执行 npm ci、npm run build 及清单测试，不安装浏览器。手机手感和视觉由用户验收。确需专项浏览器的任务单独明确入口与范围。
- 大版本/跨系统任务由审查者决定是否需要全量验收；在 Actions → PR Validation → Run workflow 选择对应分支，运行原全套回归及 Chromium/WebKit 浏览器检查。
- 旧检查显示名称暂保留，兼容可能存在的分支保护；实际范围以步骤及 Summary 为准。完整脚本、有效断言均保留。
- 不因测试失败临时缩减范围。此次调整由用户明确授权，后续任务在开发前确认清单。
